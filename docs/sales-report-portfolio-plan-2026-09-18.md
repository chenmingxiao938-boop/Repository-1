# 销售周报演示作品计划

日期：2026-09-18；更新：2026-09-23。状态：阶段7材料打包与助手验证完成，等待用户最终展示效果审查。

目标：完成一个将1–5份固定格式订单CSV整理为可核对的Excel销售周报的本地演示工具，配公开数据小样、英文说明和约一分钟录屏；用户能独立运行、解释结果和处理输入错误。

工作方式（2026-09-20用户更新）：用户只亲自做重要审查，其余实现、验证、修复及常规操作由助手自主完成；不再要求用户逐步手动操作作为推进前提。AI辅助制作，演示工具本身不调用AI处理订单或计算金额。

## 范围和安排

- 按此前每天约2小时规划，预计19–26小时，即约10–13个工作日；学习和修复时间可能延长。这是工时预算，不是交付保证。
- 新增支出目标为0，优先使用现有工具；不购买域名、订阅、广告。安装新依赖前先说明用途并确认。
- 建议路线：本地Python读取CSV，输出XLSX；第1阶段先核实现有Python、表格查看工具和所需依赖。只做选择文件、处理、保存结果的简单入口。
- 用户已改为要求助手网上查找并填写数据。作品使用UCI Online Retail公开数据并署名，标注Public dataset demo — selected records；错误测试数据另外标注Synthetic Test Data，不虚构客户或评价。
- 本演示采用GBP和2010-12-01至2010-12-05，正整数数量、非负且最多两位小数的单价；发票号以C开头的取消记录明确拒绝。原数据没有完成、付款或发货状态，不补造completed。仅核对商品行金额，不承诺税费、运费、折扣或后续退货信息完整。
- 输入1–5份文件、合计最多1000条商品明细，表结构相同；每行代表一个订单商品明细，记录ID必须跨文件唯一。
- 固定字段：line_id、order_id、order_date（YYYY-MM-DD）、sku、quantity、unit_price、currency（GBP）。order_id映射原始InvoiceNo交易/发票号；line_id由原CSV逻辑记录序号生成。SKU和其他编号按文字保留，不强制纯数字，也不人为给原数据补前导零。
- 行金额=数量×单价；金额使用整数分或精确十进制计算，不用二进制浮点累加。总额表示本演示口径下的商品销售额，不称净利润或含税实收。
- 缺列、空值、非法日期、非法金额、重复明细ID、取消发票、非GBP币种、超出范围时，指出文件及行号并停止整批；不猜数据，不补零，不自动删重。
- 原始文件保持不变；失败不生成正式报告、不把旧报告显示为本次结果；输出另存且不得覆盖输入文件。相同输入重复运行的业务结果一致。
- 先定义一个5天统计周期，周期外数据明确报错。演示不是适配任意商家的通用产品。
