# Mem0 project memory policy

## Instructions

Remember only durable project knowledge: architecture decisions, technology choices, API and database contracts, coding conventions, important user or product requirements, recurring bugs with proven fixes, deployment decisions, important limitations, and reusable lessons. Include project scope and date when a fact may become stale. Ignore secrets, API keys, access tokens, passwords, credentials, raw `.env` contents, private user data, temporary debugging output, stack traces, speculative conclusions, routine command logs, and meaningless chat history. Before storing a memory, remove sensitive values and keep only the durable decision or lesson.
